### `cost-per-verified-case` · Cost per verified case

**proxied**, verified. cost_usd, cases, errored and started_at are stored; the store fixed cost is a declared constant, not a measured billing feed, which makes this a proxy per the rubric.

- fields: `eval-store.cost_usd`, `eval-store.cases`, `eval-store.errored`, `eval-store.started_at`, `constants.store_plan_usd_per_month`
- query: Over a trailing 4-week window: (sum(cost_usd) + store_plan_usd_per_month x window_days/30) / sum(cases - errored); also $ per sweep from the latest billed run of each subject.
- **proxy:** The fixed-cost term uses the declared constant store_plan_usd_per_month rather than a Postgres billing feed, and the token x price recompute for absent cost cannot be done.
- **misses:** The constant cannot see actual plan-price changes or overages, and there is no token count or price table to recompute a $0/absent cost_usd, so a run that fails to record cost renders as free rather than recomputed.
- caveat: eval-store is ok today; spend_rows is 0, confirming there is no billing feed and the fixed term rests entirely on the constant.
- sample reading: 0.0209 — $4.69 model + $4.67 store over 447 scored cases (60 runs); $ per full sweep 1.97; BROKEN INSTRUMENT: $0 billed run(s) for concert-preview, drift-digest, incident-summary, pr-review, stakeholder-status-email
