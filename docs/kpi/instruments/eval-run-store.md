## Per KPI

### `gated-pass-rate` · Gated pass rate, per subject

**confirmed**, verified. Every input is a stored field: passed, cases, errored, model, subject, started_at are all present in eval-store. Case-weighted pass rate over the non-errored base is directly computable, as is the billed-subject minimum via the model field.

- fields: `eval-store.subject`, `eval-store.started_at`, `eval-store.passed`, `eval-store.cases`, `eval-store.errored`, `eval-store.model`
- query: For each subject take the latest row by started_at; scorable base = cases - errored; subject pass rate = passed / (cases - errored). Program-level = min over subjects where model is not null; a subject with cases - errored = 0 is reported no-signal. Deterministic subjects (model null) reported but excluded from the minimum.
- caveat: eval-store is ok today (62 runs); the value will read current where each billed subject's latest started_at is within 7 days, and stale per subject beyond that.
- sample reading: 50 tripped [stale: spec-review's latest run is 9 days old] — minimum is spec-review; spec-review 50 %; stakeholder-status-email 75 %; drift-digest 80 %; tool-selection 86 %; status-narrative 92 %; pr-review 93 %; work-breakdown 100 %; dependency 100 %; raid 100 %; concert-preview 100 %; incident-summary 100 %

### `real-cost-per-run` · Real cost per run

Nothing in the numerator comes from a price table. The definition already declares the org feed is an upper bound, which the catalog confirms.

- fields: `billing.source`, `billing.amount_usd`, `billing.kind`, `billing.period_start`, `billing.period_end`, `eval-store.started_at`, `eval-store.run_id`, `constants.store_plan_usd_per_month`

Billed dollars only from the billing feed. Report the price-table attribution beside it — but note the price table is not available (see misses).

### `cost-per-verified-case` · Cost per verified case

**proxied**, verified. The definition leans on constants.store_plan_usd_per_month (a declared constant, not a measured feed) for the fixed-cost term, and on eval-store.cost_usd whose $0/absent case has no price-table fallback in this catalog; per rubric a KPI leaning on a declared constant is a proxy.

- fields: `eval-store.cost_usd`, `eval-store.cases`, `eval-store.errored`, `eval-store.started_at`, `eval-store.subject`, `constants.store_plan_usd_per_month`
- query: model_spend = sum eval-store.cost_usd over runs with started_at in the trailing 4 weeks; store_fixed_cost_prorated = constants.store_plan_usd_per_month * (window_days / 30); cases_scored = sum(cases - errored) over the window; value = (model_spend + store_fixed_cost_prorated) / cases_scored. Per-sweep = sum cost_usd of the latest run of each billed subject.
- **proxy:** Cost per scored case computed from the store's recorded per-run cost_usd plus the declared monthly plan constant prorated, rather than from the real billing feed.
- **misses:** model_spend uses eval-store.cost_usd (which can be $0 or absent for a mis-instrumented consumer, and cannot be recomputed since the price table is not available), and the fixed cost is the declared plan constant, not the actual Heroku invoice — so it cannot see real bill drift, absent per-run cost, or a plan price that differs from the constant.
- caveat: eval-store ok today; the store_plan constant is $5.0/month and static, so this reads a computed number rather than a billed one — if no run lands in 7 days the numerator is only the fixed constant and the value reads stale, not 'cost fell'.
- sample reading: 0.0159 — $4.69 model + $4.67 store over 587 scored cases (62 runs); $ per full sweep 1.97; BROKEN INSTRUMENT: $0 billed run(s) for concert-preview, drift-digest, incident-summary, pr-review, stakeholder-status-email
- with every source removed: no value [broken: eval store unreadable: planted: source unreadable]

## Notes

- cost-per-verified-case cites the model price table for its $0/absent-cost fallback ('recomputed from tokens × price and flagged'), but both the price table and token counts are in eval-store.not_available — that fallback cannot be implemented; a $0 run must be reported broken, not recomputed.
- real-cost-per-run's so_what compares real spend to 'the price-table attribution of the same window's runs', but no model price table exists in the catalog (not_available). That comparison term cannot be computed; the unattributable-gap framing is sound but the price-table side of the ratio is missing.
- gated-pass-rate's high Goodhart risk pairs with advisory share as a counter, but per-case advisory flags are not carried by eval-store (counts only). The 'advisory share' half of the counter is unmeasurable from the snapshot; only gating case count (eval-store.cases) is available.
- All three snapshot sources (eval-store, anthropic-costs, heroku-invoices) read ok on 2026-08-27, so no KPI is broken today; per-subject staleness for the run-derived KPIs still applies against each subject's latest started_at.
- spend_rows count is 0 in the sample while billing_rows is 189 — worth confirming the billing feed rows are being read from the billing source (health shows both anthropic-costs and heroku-invoices ok), as the cost outcomes depend on them.
