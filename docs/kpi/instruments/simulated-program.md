### `forecast-slip-days` · Forecast slip

- fields: `jira.status_category`, `jira.points`, `jira.due`, `jira.issue_type`, `jira.status`, `clock.sim_date`, `clock.sim_day`
- query: remaining_points = sum(jira.points) over issues where jira.status_category != 'Done'; trailing_throughput_per_day = (points reaching Done over last 14 sim-days, computed by diffing consecutive daily jira snapshots' status_category) / 14; forecast_ga = clock.sim_date + remaining_points / throughput; committed_ga = jira.due on the issue where jira.issue_type == 'Epic'; before 14 days of history use plan rate total_points/70; if throughput==0 report broken.
- caveat: Requires 14 sim-days of prior snapshots for the trailing throughput; on today's snapshot (sim_day 1) only one day of history exists, so throughput falls back to the plan rate total_points/70 and the forecast is plan-driven, not measured.

- Jira changelog, comments, worklogs, and sprint fields are not available; every Jira KPI here correctly uses snapshot state or snapshot diffs rather than transition history, so none are affected.
